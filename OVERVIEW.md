Feishu séance connects one running Paseo agent to a Feishu (Lark) bot so you can keep the conversation going from your phone. Open an agent and choose "通灵到飞书 (Feishu séance)" from the command palette (⌘K). The bot confirms in Feishu and a "通灵中" pill appears above that agent's composer. Tap the pill to end the séance. Archiving the agent or starting a séance on another agent also ends it.

While the séance is active, each completed turn is sent to Feishu as a Markdown card. Permission requests and failed turns are sent as notifications; approving a permission still happens in Paseo. Text, images, and rich text messages you send the bot become prompts for the agent. A message that arrives during a running turn interrupts it, the same as typing in Paseo. Send `/status` to check the current séance.

Setup needs a self-built Feishu app. In the Feishu developer console, create an enterprise self-built app, add the bot capability, grant `im:message` and `im:message:send_as_bot`, choose long connection for event subscription and subscribe to `im.message.receive_v1`, then publish a version. Publishing may need approval from your tenant admin. Open a private chat with the bot and send it one message.

Then create `~/.paseo/feishu-seance.config.json` with `appId`, `appSecret`, `chatId` (the private chat that receives replies) and `allowedChatIds` (chats allowed to send prompts, defaulting to `chatId`). The Feishu client does not show the chat id: put any placeholder in `chatId`, reload the plugin, start a séance, message the bot, and read the real `oc_...` id from the plugin logs, which record the rejected chat. Set `FEISHU_SEANCE_CONFIG` to use another path. Without a config the plugin runs in dry-run mode and only writes outgoing messages to its log.

The bot is a remote prompt channel into your machine. Anyone whose messages reach an allowed chat can drive the connected agent with that agent's permissions, so keep `allowedChatIds` to your own private chat. The app secret stays on the daemon. The plugin talks only to Feishu's open platform: it sends agent replies and notifications there, and downloads images you send to a temporary file that is deleted after it is forwarded. The current séance is saved to `feishu-seance.state.json` next to the config so it survives a daemon restart.

The Feishu long connection is held only during a séance, so messages sent while nothing is connected get no reply. When several daemons share one bot, Feishu delivers each message to one random connection; end the séance on one daemon before starting it on another. After a reload or restart, turns that complete before the plugin reconnects are not sent. Feishu may redeliver unacknowledged messages and the plugin does not deduplicate them yet. Tool calls are counted, not shown, and very long replies are not split.
